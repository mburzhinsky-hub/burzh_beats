# BURZH beats

Минималистичное радио по жанрам: Future Garage, Lo-Fi, Deep House, Trance.
Монохромный дот-матричный интерфейс, альбомный «экранчик» для рабочего стола, музыка — только твоя.

**Веб-версия (iPhone, iPad, десктоп):** https://mburzhinsky-hub.github.io/burzh_beats/
Открой в Safari → «Поделиться» → «На экран Домой».

## Как работает эфир

Каждая станция — это плейлист из миксов, который крутится по общим часам. Нажимаешь play и
попадаешь туда, где эфир идёт *сейчас*, как на настоящем радио: на всех устройствах в одну
секунду играет одно и то же. Пауза = выключить радио, следующее включение — снова в живой эфир.

- Порядок миксов перемешивается на каждом круге (детерминированно, одинаково у всех).
- Если к миксу приложен треклист, на экране, на экране блокировки и в StandBy виден реальный
  трек внутри микса.
- Переключение станций — плитки, свайп по обложке, кнопки ⏮ ⏭, кнопки на экране блокировки.
- Станция без миксов показывает `OFF AIR`.

Почему часовые миксы, а не отдельные треки: на iPhone веб-плееру нельзя менять громкость,
поэтому плавные переходы между треками возможны только через Web Audio, а он ломает фоновое
воспроизведение. Сведённый микс — бесшовный звук и стабильная работа на заблокированном экране.

## Характер станций

У каждой станции свой цвет и своя планета (`accent`, `accentPaper`, `look` в `docs/stations.json`):

| Станция | Цвет | Планета |
|---|---|---|
| Future Garage | голубой | два тонких крутых кольца, «дождь» из звёзд, широкое свечение |
| Lo-Fi | янтарный | одно кольцо, крупные точки, медленное вращение с «плавающей» скоростью (плёнка) |
| Deep House | красный (фирменный) | два кольца, глубокий пульс |
| Trance | фиолетовый | три наклонённых кольца, мелкие точки, две кометы (вторая — навстречу), быстрое вращение, сильный пульс |

`accent` — цвет на чёрном, `accentPaper` — на White (оба проверяются на контраст ≥ 4,5:1 командой
`radio.py validate` и браузерными проверками). Поля `look` (все необязательные, диапазоны одинаковы в
`tools/radio.py` и `docs/planet.js`): `spin` скорость вращения, `rings` 1–3 кольца, `spread` разворот
внутренних колец, `tilt`/`roll` наклон колец, `grain` размер точек, `land` береговая линия, `halo`
свечение, `pulse` сила пульса от музыки, `flutter` плавающая скорость, `rain` дождь из звёзд, `comets` 1–2.
При смене станции цвет и форма планеты плавно перетекают в новые.

## Портретный экран

Блоки стоят колонкой, а планета забирает всю оставшуюся высоту: на высоком телефоне нет пустой
полосы, на низком планета не мельче, чем была. Работает на контейнерных единицах (iOS 16+); на старых
браузерах остаётся прежняя фиксированная раскладка. Подпись станции (`tagline`) стоит одной строкой под планетой.

## Заставка и быстрые действия

- **Заставка запуска (iPhone).** Пока приложение открывается, iOS показывает стартовую картинку вместо
  белой страницы. `python3 tools/make_splash.py` рисует 48 небольших картинок (12 размеров iPhone ×
  портрет/альбом × тёмная/светлая) и вписывает ссылки в `docs/index.html`. iOS читает их при добавлении
  иконки на «Домой»: после обновления **удали иконку и добавь заново**. Следовать теме внутри приложения
  заставка не может, только системной (тёмная / светлая).
- **Быстрые действия по долгому нажатию на иконку.** В `manifest.webmanifest` лежат `shortcuts` (по одному на
  станцию, максимум четыре; сначала станции с музыкой): они ведут на `./?station=<id>`, и приложение открывается на
  нужной станции. Работают на Android (приложение из Chrome) и на десктопе. **iPhone эту часть манифеста
  игнорирует**: быстрые действия у иконки iOS есть только у нативных приложений. Ссылка `?station=` при этом
  работает везде (закладка, ярлык «Команды»). Список обновляется командой `python3 tools/radio.py manifest`
  (и сам при `build`); `validate` сообщает, если он устарел.
- **Уменьшить движение.** Настройки → Screen → Reduce motion: Auto (как «Уменьшить движение» в настройках
  iPhone) / On / Off. В спокойном режиме планета и звёзды стоят на месте, нет колец от ударов и дождя,
  отключены все CSS-анимации (кроме микросмещения экрана против выгорания OLED).

## Альбомный экран («экранчик»)

- Огромные часы Doto, дата, погода, станция и трек; справа большая планета.
- Планета — вращающийся шар из точек. У каждой станции на нём свой «передатчик»: при смене
  станции планета делает оборот и разворачивается к нужному. Комета на орбите и свечение
  реагируют на музыку (на реальные низы, когда включена обработка звука); на каждый удар бита
  от планеты расходится кольцо.
- Шкала станций внизу читается и в «спокойном» режиме: активная — белая с цветной точкой, остальные —
  светлые, у станций без музыки пунктирная точка и метка `SOON`.
- Через 8 секунд без касаний кнопки уходят, остаются часы, планета, шкала станций и прогресс;
  первое касание только будит экран.
- Экран не гаснет в альбомной ориентации (Screen Wake Lock, iOS 18.4+).
- Ночной режим: та же палитра, только приглушённая. По умолчанию выключен; AUTO — с 23:00 до 7:00.
- Защита OLED от выгорания: раз в минуту картинка смещается на несколько пикселей.
- Погода: Open-Meteo, по запросу геопозиции (Настройки → Экран → Weather). Координаты хранятся
  только в браузере, округлённые до ~1 км.

**StandBy на iPhone.** Свой интерфейс в системный StandBy веб-приложение встроить не может —
туда попадают только виджеты нативных приложений. Когда играет радио и телефон заблокирован,
StandBy и экран блокировки показывают системную карточку «Сейчас играет» с обложкой станции
(`docs/art/*.png`), названием трека и кнопками переключения станций.
Хочешь именно свой экранчик — оставь приложение открытым в альбомной ориентации на зарядке.

## Проверки (чтобы после каждой правки ничего не отваливалось)

- `python3 tools/radio.py validate` — станции, обложки и **сами аудиофайлы** (AAC, faststart, без видеодорожки,
  длительность совпадает с `stations.json`, размер).
- `cd tests && npm install && node run.js` — 71 браузерная проверка на настоящих файлах `docs/`: старт и
  остановка, бесшовное переключение звука и пресетов, паузы iOS, «молчащий» движок, запасные варианты
  (движок → обычный плеер → без `#t=`), **медленный сервер, обрыв связи, зависшее соединение**, прогрев
  CDN, запуск из сохранённого списка, офлайн-оболочка и обновление приложения, перемотка мышью и
  пальцем, настройки, погода, фон Black/White (контраст всего текста, холсты, ночной режим), вёрстка
  на 10 экранах, характер станций (цвета, контраст, плавный переход планеты, кольца от ударов), «уменьшить
  движение», быстрые действия и `?station=`, стартовые картинки, шкала станций, портретная раскладка без наложений на 7 экранах, части длинного микса (порядок, счёт, один микс на экране и в перемотке, неизменное расписание, нарезка `radio.py`). Скриншоты — в `tests/out/`. `node run.js seek layout` запускает только нужные.
- GitHub Actions: релиз **не публикуется**, пока эти проверки не прошли; после публикации
  `tools/live_check.py` запрашивает с живого сайта каждый микс так же, как телефон (Range, CORS, размер).
- Если музыка не играет: Настройки → About → **Last playback problem** показывает причину (код ошибки
  плеера и ответ сервера) — достаточно скриншота.

## Быстрый старт и медленная сеть

GitHub Pages отдаёт файл, который давно никто не просил, **медленно**: «холодный» запрос к аудио
занимает 1–4 секунды (замер из CI: холодный 1.0–3.7 с, прогретый 20–35 мс), а Safari до первого
звука делает три запроса подряд. Отсюда долгий старт. Что с этим сделано:

- **Прогрев.** При запуске, при выборе станции, при возврате в приложение и каждые 20 секунд приложение
  само просит у CDN первые 2 байта текущего микса (и следующего — за 4 минуты до смены). Одного такого
  запроса достаточно, чтобы вся запись попала в кэш CDN: к нажатию Play каждый запрос — 20–35 мс.
- **Сторож загрузки различает причины.** Тихо 6 секунд → приложение само спрашивает сервер (64 КБ):
  не отвечает — «нет связи», повтор с нарастающей паузой; отвечает медленно — «SLOW NETWORK», ждёт
  дальше и **ничего не перезапускает** (до 60 с); отвечает быстро, а плеер молчит — если у элемента
  открыт запрос (`networkState = LOADING`), он работает, просто медленно (Safari делает несколько
  круговых запросов до первого звука), и ему дают до 20 с; «зависшее соединение» — это тишина без
  открытого запроса или 20 с без данных, тогда один перезапуск загрузки. Раньше любая медленная
  загрузка считалась поломкой.
- **Звуковой движок виноват только если обычный плеер заработал там, где он нет.** Сбой движка —
  не приговор: после одного сбоя он пробуется снова при следующем Play, после двух — отдыхает, пока
  не переключишь Sound shaping (выкл/вкл). Переключатель Sound shaping остаётся рабочим всегда.
- **Прерывание звука не считается поломкой.** Звонок, Siri, смена выхода, блокировка экрана останавливают
  `AudioContext`, а музыка идёт через него и замолкает. Приложение каждую секунду проверяет цепочку:
  пробует `resume()`, а если контекст не поднялся 6 с при видимом экране — продолжает на обычном плеере
  (без «страйка») и по **тапу в любом месте** возвращает Sound shaping (iOS запускает контекст только
  в жесте; не чаще раза в 15 с и не больше 3 раз, переключатель Sound shaping сбрасывает счётчик).
- **Приложение открывается из сохранённой копии** (service worker, cache-first) и из сохранённого
  списка станций, не дожидаясь сети. Новый релиз скачивается целиком в фоне и подхватывается, когда
  это ничего не стоит: музыка не играет и настройки закрыты. Каждый релиз получает собственный
  идентификатор (`BUILD` в `docs/sw.js` подставляет CI), CI проверяет, что он попал на сайт.
- **Диагностика** — Настройки → About: **Last start** (сколько заняло включение и сколько из них — до
  первых данных), **App launch**, кнопка **Test connection** (первый байт, скорость на 1 МБ, `x-cache`
  — попал ли запрос в кэш CDN) и **Refresh app** (забыть все сохранённые копии и загрузить заново).
- **Event log** (там же): последние 160 событий — запуски, Play/Stop, каждый запрос и ответ загрузки с
  секундами от старта, решения сторожа, состояние звукового движка, сворачивание/возврат, ошибки.
  Хранится на устройстве и **переживает перезапуск приложения**. «Copy report» кладёт в буфер отчёт
  (устройство, режим, сохранённая копия, скорость сети, настройки звука, события) — достаточно вставить
  его в чат; «Share» отправляет его через меню iOS.

Проверить сайт глазами реального Chrome с настоящими файлами и сетью GitHub: Actions →
**Live end-to-end** (запуск вручную) — время запуска и время от Play до первого звука (звук-обработка
выкл/вкл) приходят аннотациями (`tests/live.js`).

## Фон: Black и White

Настройки → Screen → Background. **White** — «бумажная» палитра в духе Nothing: тёплый белый фон
`#F1F1EE`, чернильный текст `#111`, карточки `#FAFAF8` и один красный акцент (станционный красный
на 20 % темнее, чтобы мелкий красный текст читался). Ночной режим всегда чёрный (OLED), даже при White.

Все цвета — переменные CSS в `docs/index.html` (`:root` = Black, `html.theme-white` = White); новая палитра
добавляется одним блоком. Холсты (планета, эквалайзер) берут цвета через `docs/theme.js`.
Прежний «Graphite» автоматически становится White. На iPhone строка состояния всегда белая
(`black-translucent`), поэтому в портрете на White под ней тёмная полоса высотой в safe-area.

## Перемотка (time-shift)

Полоска внизу — ползунок: тяни её (или просто тапни) и музыка перейдёт на нужное место внутри
текущего микса, например с 10-й минуты на 40-ю. Над пальцем показывается время и сколько
это впереди/позади эфира. Статус меняется на **TIMESHIFT**, рядом появляется кнопка **↺ Live** —
она возвращает в прямой эфир. Когда микс закончится, играет следующий с начала; Stop и смена
станции тоже возвращают в эфир. С клавиатуры: ←/→ ±10 с, Shift или PgUp/PgDn ±1 мин,
Home/End. Перемотка работает и с экрана блокировки/StandBy (Media Session `seekto`).

## Звук

Настройки → Sound → **Sound shaping**. Цепочка Web Audio:

```
вход → trim → rumble-фильтр → 6-полосный EQ ─┬─ сухой сигнал
                                              ├─ бас-энхансер (гармоники саба)
                                              └─ clarity (гармонический «воздух»)
  → ширина стерео (mid/side, только выше 150 Гц) → glue-компрессор → level → лимитер
```

- Пресеты: Auto (по станции: Club для Trance, Deep для Deep House, Warm для Lo-Fi, Wide для
  Future Garage), Flat, Club, Deep, Warm, Wide, Clear, Night и твой Custom.
- Эквалайзер рисуется живой кривой поверх спектра: тяни точки, двойной тап сбрасывает полосу.
- Автоматический запас по уровню: подъём EQ компенсируется на входе, лимитер ловит остатки.
- Звуковая цепочка подключается один раз — при первом нажатии Play, и дальше плеер её уже не
  меняет. Переключатель Sound shaping и смена пресетов только меняют параметры цепочки, поэтому
  музыка не прерывается и не перезапускается. «Выкл» — нейтральный обход (плоский EQ, без
  энхансера). Обычный `<audio>` остаётся запасным вариантом, если веб-аудио недоступно.
- Страховка: если цепочка молчит или не стартует, приложение само возвращается на обычный звук и
  сообщает об этом (плашка и About). Это временная мера: движок пробуется снова при следующем Play,
  после двух неудач — когда переключишь Sound shaping выкл/вкл. Переключатель не блокируется, а
  «Not supported» показывается только если Web Audio в браузере действительно нет.
- На iPhone веб-аудио при блокировке экрана может остановиться — проверь на своём телефоне. Если
  так, дай знать: можно будет добавить режим «обычный звук», безопасный для блокировки.
- Нужны аудиофайлы с того же домена или с CORS (для внешнего хранилища добавь
  `Access-Control-Allow-Origin`). Иначе приложение само отключит обработку и продолжит играть.
- Какой пресет у станции — поле `"sound"` в `docs/stations.json`.

## Добавить музыку

Нужен `ffmpeg` (`brew install ffmpeg`).

```bash
python3 tools/radio.py build          # первый запуск создаст папки library/<станция>/
# положи файлы: library/lofi/night-tape-01.mp3 (+ night-tape-01.txt с треклистом, по желанию)
python3 tools/radio.py build          # перекодирует и обновит docs/stations.json
python3 tools/radio.py list           # что сейчас на станциях
git add docs && git commit -m "Add Lo-Fi mixes" && git push
```

`build` делает для каждого файла:
- выравнивание громкости до −14 LUFS (двухпроходный EBU R128) — все станции звучат одинаково;
- AAC 128 kbps `.m4a` с faststart — мгновенный старт и перемотка;
- название и артист берутся из тегов файла или из имени;
- треклист из `.txt` (строки вида `00:00 Artist - Title` или `1:02:33 Title`) или `.cue`;
- **очень длинный микс режет на равные части** (GitHub не принимает файлы больше 100 МБ, `build` режет всё,
  что тяжелее ~80 МБ, то есть примерно от 1 ч 10 мин): место разреза — самый тихий момент возле середины,
  громкость у всех частей одинаковая, треклист делится по частям. Части получают общий `group` в `stations.json`
  (`mix-01-part1.m4a`, `mix-01-part2.m4a`), и радио всегда играет их подряд и по порядку — перемешиваются только
  целые миксы. Слушатель частей не видит: одно название, длина всего микса, полоса и перемотка через разрез
  (на экране, на экране блокировки и в StandBy).

Папка `library/` в git не попадает. Уже перекодированные файлы повторно не обрабатываются.
Старые миксы остаются в станции; `--prune` удаляет те, которых больше нет в `library/`.

### Хранение аудио вне git

Сейчас миксы лежат в `docs/media/` и раздаются GitHub Pages. Для большой библиотеки лучше
внешнее хранилище (например, Cloudflare R2 с публичным доменом):

```bash
python3 tools/radio.py build --out dist-media --media-base https://media.example.com/burzh/
# загрузи dist-media/ и текущие docs/media/* в хранилище, затем удали docs/media из репозитория
```

Можно также добавить станцию-поток: вместо `items` укажи `"stream": "https://…/stream.mp3"`.

### Новая станция

Добавь объект в `docs/stations.json` (`id`, `name`, `glyph`: `grid|wave|rings|tri`, `accent` и `accentPaper`,
`look` — характер планеты, `tempo` — период орбиты в секундах, `sound` — пресет звука, `tagline`, `art`) и
выполни `python3 tools/make_art.py` (обложка) и `python3 tools/radio.py manifest` (быстрые действия).
Плитки и меню жанров строятся из `stations.json` автоматически.

## Android

Приложение в `app/` — тонкая оболочка (WebView) над той же веб-версией: одни станции, один эфир.
Нативная часть добавляет вибро-отклик и удержание экрана для альбомного режима; переходы на
чужие сайты открываются в браузере. Каждый пуш с изменениями в `app/` собирает debug APK
(GitHub Actions → артефакт `BURZH-beats-debug-apk`).

## Проверки

`python3 tools/radio.py validate` проверяет `stations.json`, наличие аудио, размеры и целостность
иконок и обложек. Запускается в CI на каждый PR (`.github/workflows/check-web.yml`).

Иконки и обложки перерисовываются командой `python3 tools/make_art.py`, стартовые картинки — `python3 tools/make_splash.py`.
